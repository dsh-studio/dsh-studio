# 长文调研报告

## 流程（必须按序）

1. **对齐问题**:把用户的话改写成 2-4 个可检索的具体问题,连同交付形态(报告放哪、多长、给谁看)一句话跟用户确认。用户不回复细节时按默认走:`调研-主题-日期.md` 存到当前工作区,2000-4000 字。
2. **多角度检索**:每个问题至少换 2 种关键词搜索(中文+英文各试),优先官方文档/官网公告/一手数据,其次行业评测,最后论坛观点。记下每条关键信息的来源 URL。
3. **交叉验证**:关键结论(价格、日期、政策、数据)必须有 2 个独立来源;只有单一来源的,在报告里标注"单一来源,待核实"。
4. **成文**:按下面的报告骨架写 Markdown 文件,先写结论。
5. **汇报**:给出文件路径 + 三句话摘要 + 哪些点没查到或存疑。

## 报告骨架

```
# 标题(主题 + 日期)
## 结论先行(3-5 条,可执行的判断)
## 对比表(如果是选型/竞品类)
## 分项展开(每项:事实 → 来源 → 判断)
## 风险与存疑(没查到的、来源冲突的、时效性差的)
## 来源清单(全部 URL,标注访问日期)
```

## 铁律

- **事实和推断分开写**:推断句必须带"推测/可能/按 X 推算"字样。
- 查不到就写查不到,禁止编造数字、价格、日期、政策。
- 中文互联网信息优先核对发布日期,超过一年的价格/政策类信息必须标注时效。
- 报告是新建文件,不改用户的任何现有文件。
